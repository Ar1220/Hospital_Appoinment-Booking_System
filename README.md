# Requiem Medical Center — Hospital Appointment Booking System (MySQL)

A dark, cinematic hospital booking site (React + Vite) wired to a real **MySQL** database through an
Express API. This is the **SQL half** of the SQL / NoSQL project pair.

> **Note:** this is a small university project — the SQL/NoSQL assignment. The whole
> "Resident Evil hospital" look is just me having fun with the UI; the point of the project is the
> database: schema, relationships, view, stored procedures, and a working booking flow on top of it.

```
React 19 + Vite (port 5180)
        │  fetch  →  http://localhost:3002/api
        ▼
Express API (port 3002)  ──mysql2 pool──▶  MySQL 8 (Docker, port 3307)
                                             requiem_hospital DB
```

## 1. Stack

| Layer     | Tech                                   | Port |
|-----------|----------------------------------------|------|

> 3306 is used by another MySQL container and 3001 by a local gateway, so this project uses

## 2. Quick start

**Easiest: double-click `services.cmd`** — it shows a green/red dot for each service and lets you
start all, stop all, view DB data, or open a MySQL console (menu options 1–6).

Manual start:

```bash
# 1. Database (first run creates the schema automatically)
docker compose up -d

# 2. Backend API
cd backend
npm install
npm start          # or: npm run dev (nodemon)

# 3. Frontend
cd ..
npm install
npm run dev        # http://localhost:5173 (Vite default)
```

Open the site, scroll to **Begin your record**, fill the intake form, submit.
You get back a real appointment number (`APT-YYYY-MM-DD-#####`) and confirmation code
generated by MySQL.

### Manual DB load (if the container already had a data volume)
```bash
docker cp database/schema.sql requiem-mysql:/tmp/schema.sql
docker exec requiem-mysql sh -c 'mysql -uroot -prequiem_root_2025 < /tmp/schema.sql'
```

### Credentials
| What | Value |
|------|-------|
| DB host / port | `localhost` / `3307` |
| DB user / pass | `root` / `requiem_root_2025` |
| DB name | `requiem_hospital` |

Stored in `backend/.env` (git-ignored) and `docker-compose.yml`.

## 3. Database design

`schema.sql` creates **7 tables**, **1 view** and **2 stored procedures**.

| Table | Purpose |
|-------|---------|
| `doctors` | Clinicians shown in the directory; `status` + `availability_note` drive the live availability pill |
| `appointment_types` | Bookable services (`EMG`, `SUR`, `DIA`, `SPC`, `RUT`) with duration |
| `appointments` | The booking record — patient identity, chosen doctor/type, date+time, emergency contact, status workflow (`pending → confirmed → in_progress → completed / cancelled / no_show`), confirmation code |
| `services` | Marketing service cards |
| `facilities` | Facility/room gallery |
| `testimonials` | Patient quotes (`is_featured` flag powers the API filter) |
| `newsletter_subscribers` | Footer signup, unique email |

Extras:
- **View `appointment_details`** — joins appointments × doctors × types so the API returns names, not just IDs.
- **`GenerateAppointmentNumber(OUT …)`** — sequential `APT-<year>-<month>-00001` per month.
- **`CreateAppointment(...)`** — transactional insert that assigns number + 6-char confirmation code.

Seed data: 4 doctors (Leon S. Kennedy, Ada Wong, Dr. Victor Gideon, HAOS), 5 appointment types,
4 services, 3 featured testimonials.

## 4. API reference (base `http://localhost:3002/api`)

| Method | Endpoint | Notes |
|--------|----------|-------|
| GET | `/health` | DB connectivity check |
| POST | `/appointments` | Create booking → `{appointmentNumber, confirmationCode}` |
| GET | `/appointments` | All bookings via `appointment_details` view |
| GET | `/appointments/:id` | Single booking |
| GET | `/appointments/confirm/:code` | Lookup by confirmation code |
| PATCH | `/appointments/:id/status` | Change workflow status |
| GET | `/doctors` · `/doctors/:id` | Clinician directory |
| PATCH | `/doctors/:id/status` | Update availability |
| GET | `/appointment-types` | Bookable services |
| GET | `/services` · `/testimonials` | Marketing content |
| POST | `/newsletter` | Subscribe (validates email, dedupes) |
| GET | `/stats/overview` | Counts for a dashboard |

## 5. Frontend ↔ API wiring

- `src/api.ts` — typed client. Base URL from `VITE_API_URL` (`.env`), default `http://localhost:3002/api`.
- On mount the app loads **doctors** and **appointment types** from MySQL (static seed arrays are only a
  fallback if the API is unreachable).
- Submitting the form `POST`s to `/appointments`; the confirmation dialog shows the real
  appointment number + confirmation code returned by the database.
- Footer newsletter posts to `/newsletter`.

## 9. Troubleshooting

| Symptom | Fix |
|---------|-----|
| `EADDRINUSE :3002` | Another server is running: `netstat -ano \| grep 3002`, kill that PID |
| API returns `Error creating appointment` | Check `docker ps` — container down? Check date/time values are valid (`YYYY-MM-DD` / `HH:MM`) |
| Site loads but doctors look static | API down; open `http://localhost:3002/api/health` |
| Need a clean DB | `docker compose down -v && docker compose up -d` (drops the volume, re-runs schema) |
